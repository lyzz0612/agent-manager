# 项目说明

## 1. 项目定位

`agent-manager` 不是一个对话式 agent 平台，也不是通用终端托管工具。  
Phase 1 的目标是做一个面向单用户的 Cursor CLI 管理器，先运行在 VPS 上，通过网页管理容器内受管的 Cursor 环境。

它要解决的问题是：

- 如何在 VPS 上安装和升级受管的 Cursor
- 如何通过网页查看和引导 Cursor 登录
- 如何管理 Cursor 的关键配置和原始配置文件
- 如何管理已有的 user 级 skill
- 如何让部署、发布和本机验证形成闭环

## 2. Phase 1 范围

Phase 1 明确包含：

- 只支持 `Cursor`
- 单用户
- 容器内受管运行时
- 手动安装和手动升级
- 网页管理入口
- 固定 Token 登录管理页
- Cursor 登录引导
- best-effort 账号展示
- 配置管理
- 已有 skill 管理（列出 / 编辑 / **从远程仓库安装**）
- Docker 单容器部署
- GitHub Actions 自动发布镜像
- 项目级文档体系

## 3. 非目标

当前阶段明确不做：

- 多 CLI 支持
- 多用户、多租户
- 对话、session、终端托管
- skill 搜索 / 更新 / 卸载的可视化（v1 安装向导仅 preview + install）
- 卸载能力
- 桌面端功能实现
- 审计、历史记录和复杂任务系统

## 4. 用户与使用场景

当前目标用户就是项目维护者本人，使用场景以单用户 VPS 为主。

典型流程是：

1. 在 VPS 上部署 `agent-manager`
2. 通过网页登录管理页
3. 安装或升级容器内受管的 Cursor
4. 引导完成 Cursor 登录
5. 管理关键配置、原始配置和已有 skill
6. 使用 Docker 和镜像发布链路进行验证和迭代

## 5. 未来方向

未来会扩展到桌面端，但当前阶段只是预留边界：

- React UI 尽量复用
- Rust Core 尽量复用
- `Tauri` 作为未来桌面宿主

桌面端不会纳入本次实现范围，会在后续单独展开。
