## ADDED Requirements

### 需求:系统必须以单容器形式交付 Web 和 Core
系统必须支持以单个应用容器交付服务端和 Web 前端，并且必须由服务端托管前端构建产物。

#### 场景:容器启动后提供管理界面
- **当** 应用容器成功启动
- **那么** 系统必须能够同时提供管理 API 和 Web 管理界面

### 需求:系统必须提供当前分支驱动的镜像发布流程
系统必须在当前分支的 push 触发 GitHub Actions，并且必须构建 `linux/amd64` 镜像发布到 `ghcr.io`。普通提交也必须生成新的正式 `X.Y.Z` 版本号，并更新 `latest` 标签。

#### 场景:普通提交触发发布
- **当** 当前分支有新的普通提交触发 workflow
- **那么** 系统必须构建并发布新的 `X.Y.Z` 镜像
- **那么** 系统必须同时更新 `latest`

### 需求:系统必须使用根目录 VERSION 作为唯一版本源
系统必须使用仓库根目录的 `VERSION` 文件作为唯一权威版本源。自动构建后必须回写更新后的版本号，并且回写提交必须不再次触发同一发布流程。

#### 场景:自动递增并回写版本
- **当** 普通提交触发自动构建
- **那么** 系统必须读取当前 `VERSION`
- **那么** 系统必须自动递增最后一位并回写到 `VERSION`
- **那么** 系统必须通过 GitHub Actions bot actor 防止回写提交再次触发 workflow

#### 场景:手动或 tag 指定版本
- **当** 用户手动指定版本，或通过 `vX.Y.Z` tag 指定版本
- **那么** 系统必须使用该指定版本进行构建
- **那么** 系统必须把该版本同步回写到 `VERSION`

### 需求:系统必须提供最小可运行的本机与 Compose 入口
系统必须为开发者提供本机开发态快启和 `docker compose` 验收两类入口。官方 Compose 示例必须默认使用 `latest`，并且默认不包含持久化挂载。

#### 场景:使用官方 compose 示例
- **当** 用户使用官方提供的 compose 示例
- **那么** 系统必须默认拉取 `latest`
- **那么** 系统必须不强制包含数据挂载配置
